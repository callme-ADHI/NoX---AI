## 5. PHASE 4: CONNECTOR FRAMEWORK, MAIL, CALENDAR

### 5.1 Framework
 Connector interface: auth (connect/refresh/revoke), health (typed reasons: auth, network, rate_limited, quota, service_down, misconfigured), sync (incremental, resumable), fetch/search, optional guarded write, rate-limit and backoff handling, per-connector privacy class (local_only default; cloud_allowed opt-in), data retention and delete. Registered in a catalog table and config file ~/.config/nox/connectors.toml (no secrets). A failing connector degrades to a "degraded" state with a visible reason and never blocks daemon start or other connectors. Sync runs as supervised tasks (Session L semantics: heartbeat, timeout, resume, notification on final failure).

### 5.2 Gmail and IMAP
 - Gmail via the REST API with httpx: OAuth installed-app flow with PKCE and a loopback redirect, default scope gmail.readonly only; gmail.compose (drafts) and gmail.send are separate opt-in scopes. Tokens go to the secret store. "nx connect gmail", "nx disconnect gmail" (revokes and deletes local data on request). Document the Google Cloud OAuth-client setup as USER-RUN in docs/CONNECT_GMAIL.md. Generic IMAP over SSL with an app password as the no-OAuth alternative ("nx connect imap"), including Outlook/Yahoo/custom servers.
 - Local mail store: mail_items (account, message id, thread id, labels, from domain and name, date, subject, sanitised text truncated to 20 KB, flags, extracted fields), attachments as metadata only (PDF/text extraction capped at 1 MB and only on demand; never open executables or macros), retention default 90 days, delete controls. Never fetch remote content from emails automatically (no tracking pixels, no link prefetch).
 - Calendar: Google Calendar read-only (same OAuth, separate scope) and ICS file/URL import as a no-OAuth path; events feed the digest and deadline extraction.

### 5.3 Mail intelligence driven by an editable MAIL PROFILE
 The profile is a user-editable file/UI form (versioned like briefing prompts) with: priority topics and senders (for example college/KTU, internships and opportunities, hackathons, GitHub, placements), VIP senders/domains, categories with rules (College, Opportunities, Hackathons/CTF, GitHub and CI, Payments and Banking [always local-only], Newsletters, Personal, Noise), what counts as urgent, digest times (default: attached to the morning and evening briefings), summary length and style, language. Chat edits work too ("treat internship mails as urgent", "ignore promotions").
 Pipeline: sync, rule-based pre-classification (cheap, deterministic), model classification of the rest, extraction of deadlines, events, action items and links, then outputs:
 - Digest: a new "Mail" section in the briefing and "nx mail digest [--since 24h]"; triage buckets Action needed / Deadlines / FYI / Noise with counts, plus thread summaries and "why this matters".
 - Search and Q&A: "nx mail search ..." and chat questions ("what did X say about Y") with citations to message ids (local view only).
 - Proposals, never silent actions: deadlines and events become proposed reminders/jobs the user approves with one click; unsubscribe suggestions are lists only.
 - Reply drafts: saved as drafts (Gmail draft or local draft). Sending needs an approval with the full preview and exists only if the send scope was opted in; per-message confirmation every time; never auto-reply.
 - Phishing and safety flags: display-name/domain mismatch, lookalike domains, urgency plus link, mismatched link text/target; warnings shown with the digest. Link display shows the real domain.
 Model policy: local models by default. The local 14B model is too slow (about 2 tokens/s on this machine) for bulk summarisation, so benchmark installed small local models and choose one (print the exact "ollama pull" line if none is suitable); batch and cache; extractive fallback (subject plus first lines) labelled "degraded". Budget: a digest of 150 new mails completes in 10 minutes or less. Cloud summarisation is opt-in per account/label (never for Payments and Banking), always after the redactor, and always through the KeyPool.
 Tests: protocol-level fake IMAP server and fake Gmail/Calendar HTTP server exercising the real clients (incremental sync, resume, 401 refresh, 429 backoff, malformed MIME, huge attachment, HTML injection payloads with instructions inside the body that must not change behaviour), classifier tables, redaction before cloud, draft and send approval flows, retention delete. USER-RUN live checks: "nx connect gmail" and "nx selftest --live mail" printing counts only.
